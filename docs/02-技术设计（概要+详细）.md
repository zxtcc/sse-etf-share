# 项目概要技术设计和详细技术设计

## 概要设计

项目采用 Flask 提供 Web 页面和查询 API，使用 requests 访问上海证券交易所接口，使用 openpyxl 将 ETF 数据保存为 Excel。前端通过 `fetch` 调用后端接口并渲染结果。

## 模块设计

- `app.py`：Flask 入口，提供首页、`/api/query` 单日查询接口和 `/api/update` 数据更新接口。
- `sse_client.py`：封装上交所接口调用、分页查询、输入校验、数据解析和单位换算。
- `storage.py`：负责 `data/ETF代码.xlsx` 的读写，以及全量日期状态记录。
- `templates/index.html`：双板块页面，负责表单提交和结果展示。

## 接口设计

### `POST /api/query`

请求 JSON：

```json
{
  "code": "510050",
  "date": "2025-09-04"
}
```

成功响应：

```json
{
  "success": true,
  "data": {
    "stat_date": "2025-09-04",
    "code": "510050",
    "name": "上证50ETF华夏",
    "short_name": "50ETF",
    "etf_type": "单市",
    "total_volume_10k": "5833506.68",
    "total_volume_shares": 58335066800
  }
}
```

其中 `source` 字段表示数据来源，取值为 `local` 或 `sse`。

失败响应：

```json
{
  "success": false,
  "message": "未查询到该 ETF 在指定日期的份额数据，请确认代码或选择交易日。"
}
```

### `POST /api/update`

请求 JSON：

```json
{
  "start": "2025-09-04",
  "end": "2025-09-04"
}
```

成功响应：

```json
{
  "success": true,
  "summary": {
    "date_count": 1,
    "fetched_date_count": 1,
    "skipped_full_date_count": 0,
    "skipped_weekend_count": 0,
    "empty_date_count": 0,
    "saved_record_count": 715
  }
}
```

## 数据流

1. 前端提交 ETF 代码和日期。
2. 后端校验代码必须为 6 位数字，日期必须为 `YYYY-MM-DD`。
3. 后端先读取本地 Excel；命中则直接返回。
4. 本地缺失时，后端请求上交所 `commonQuery.do` 接口。
5. 后端在列表中按 ETF 代码匹配记录，保存到 `data/ETF代码.xlsx`。
6. 后端返回结构化 JSON，前端展示结果。

## 数据汇总流程

1. 后端校验起止日期，终止日期不能晚于最近一个非周末日期。
2. 后端遍历日期区间，跳过周末。
3. 如果 `data/_update_status.json` 已标记该日期全量更新，则跳过。
4. 对未更新日期，后端按分页请求上交所 ETF 全量列表。
5. 每次请求后随机休息，降低访问频率。
6. 全量数据按 ETF 代码分组，写入对应 Excel 文件。
7. 保存成功后，将日期标记为已全量更新。

## 关键处理

- 上交所 ETF 规模接口不按 ETF 代码筛选，单日查询按日期取列表后在服务端过滤。
- 数据汇总使用分页循环，直到上交所返回的 `pageCount` 全部处理完成。
- `data/_update_status.json` 只在 Excel 保存成功后更新，避免状态和文件不一致。
- `TOT_VOL` 单位是“万份”，程序使用 Decimal 做数值解析，并换算为“份”。
- 非交易日、代码不存在或接口当天无数据时，统一返回友好提示。
